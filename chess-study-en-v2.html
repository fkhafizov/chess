Move-pair graph (White move, Black reply)

Every vertex is a position with White to move. Every edge is a pair of moves: a White move and Black's reply. If the White move is checkmate, the edge ends in a red vertex (there is no Black reply). No path is longer than N edges. A handy analogy: this is an AND–OR tree — White only needs to find one good move (OR), but must then cope with every Black reply (AND).

How to use

  • Vertices are positions with White to move (green). A red vertex is the position after a mating White move; its edge carries the White move only. Gray is stalemate (White's move stalemated Black). A dashed vertex was not expanded because of the vertex limit.
  • An edge is labelled with the pair White move, Black reply in short algebraic notation (SAN); the label sits above the vertex the edge leads to. White's moves from the root are numbered as move 1.
  • N is the maximum number of edges on any path from the root, i.e. mate must occur no later than White's N-th move. N ranges from 1 to 20.
  • Modes.
    • Forced mate within N only (default). Only those White moves are shown after which mate is forced no later than move N against any defence; all Black replies are shown. This is exactly the solution tree of a "mate in N" problem. The shortest mates only box (off by default) keeps, in each position, only the moves that mate in the minimum number of moves (it removes duals and slow lines); the search then uses iterative deepening and is fast even at N = 20. With the box off, all mating moves within N are shown — that requires a full search to depth N and takes tens of seconds at N ≥ 4.
    • Full tree with vertex limit. All legal moves of both sides, breadth-first; when the number of vertices reaches the limit, the remaining vertices are marked dashed. The full tree grows roughly like 150N, so the limit almost always kicks in already at N = 2.
    • Full tree, no pruning. The same without a limit — only for very small N (at N ≥ 3 it is millions of vertices and the browser may hang).
  • Vertex limit applies when the apply vertex limit box is checked (except in "no pruning" mode, which never has a limit). The limit is a ceiling, not a target: if the whole tree is smaller than the limit (e.g. 32 vertices with a limit of 40), the whole tree is drawn and the limit has no effect; only when the tree would be larger does the build stop exactly at the limit and mark unexpanded vertices with dashes. Uncheck the box to see the whole tree regardless of size — e.g. the complete solution tree in forced-mate mode. The search is also aborted after 5·106 nodes or 120 s.
  • Start builds the graph; Reset clears the graph and restores the default parameters; Help opens this window.
  • Navigation: drag to pan, mouse wheel / pinch to zoom, double-click to fit the graph to the window. Tapping a vertex shows the diagram, the path from the root and a lichess link.
  • The rules are implemented inside the file (no libraries): all pieces, en passant, promotion (to Q, R, B, N). Castling is not supported — studies of this kind never need it.
